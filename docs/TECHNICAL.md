# 기술 설명

## 디스크 구성

| 파일 | 내용 |
| --- | --- |
| `CAP0.EXE`~`CAP4.EXE`, `CAPX.EXE` | 챕터별 실행파일(시작의 소문, 첫~네 번째 소문, 또 하나의 소문) |
| `DAT/CAPn/*LINK.CDB` | 챕터 데이터. 대본·배경·그림이 들어 있는 CDB 컨테이너 |
| `DAT/FONT/KFONT.CDB` | 챕터별 대사 글꼴 |
| `DAT/ALLCAP/KALINK.CDB` | 공통 그림(옵션 메뉴 라벨, 게임오버, 챕터 타이틀 카드) |
| `DAT/SINKOU/ALLLINK.CDB`, `MENUDAT.BIN`, `MEMDAT.BIN` | 진행 화면(세로쓰기 챕터 제목, 타이틀 「시작/준비」, 장소 이름, 메모리 카드 안내) |

CDB는 2048바이트 헤더에 `[시작 섹터 u16, 섹터 수 u16]` 엔트리 표가 있고 데이터는 섹터 단위로 정렬됩니다(`tools/cdb.py`). 재패킹하면 크기가 바뀔 수 있어, 디스크의 파일 영역을 교체하거나 빈 곳으로 옮기고 ISO9660 디렉터리를 고칩니다(`tools/disc.py`, `tools/iso.py`, 섹터 EDC/ECC 재계산 `tools/cdsec.py`).

## 압축

엔트리 안 데이터는 여러 개의 압축 덩어리가 이어 붙은 형태입니다. 명령 바이트 `00~7F` 리터럴, `80~BF` 런, `C0~DF` 역참조(거리 16비트), `E0~EF` 등차 수열, `FF` 끝입니다(`tools/lz.py`). 그림 덩어리는 게임이 오프셋으로 찾아가므로 `comp_fit`으로 다시 압축한 결과를 원래 길이와 정확히 같게 맞춥니다(모자라면 리터럴로 채움).

## 대본

- 대본은 u16 토큰 스트림을 압축한 블록의 나열입니다. 토큰은 글꼴 코드(문자)와 `8xxx`·`Cxxx` 제어 태그(줄바꿈 대기, 페이지 넘김, 선택지, 표정·효과 등)로 이루어집니다(`tools/script.py`, `tools/tok.py`).
- 번역은 블록 번호별 `{"id","ko"}` JSON이며, 제어 태그는 `{8408}` 형태로 원문과 같은 순서·개수를 유지합니다(`tools/chk.py`가 태그·줄 수·한 줄 폭 272px 이하를 검사).
- 블록 길이가 바뀌므로 실행파일 안의 블록 포인터(`0x801F0000+오프셋`)를 새 위치로 고칩니다(`tools/ptrs.py`).

## 글꼴

- 원래 대사 글꼴은 고정 글리프 표를 실행파일이 직접 참조합니다. 한글 글꼴은 `KFONT.CDB`의 챕터별 엔트리를 교체해 0x8001A200에 올립니다.
- 엔트리 구조: `+0` 원본 CLUT(그대로 유지해야 함), `+0x70` 2bpp→4bpp 확장 루틴(MIPS), `+0x100` 글리프 표 `{포인터, 폭}`×N, 그 뒤 16×16 2bpp 글리프(64바이트씩). 실행파일의 표 참조 3곳과 글리프 디코더 호출을 새 주소로 고칩니다.
- 코드 0x000~0x10B는 원본 공통 글리프(숫자·기호 등), 0x10C부터 그 챕터 대본에 쓰인 한글을 빈도순으로 배정합니다. 글자는 비례폭입니다.

## 그림 글자

TIM(4bpp/8bpp) 그림의 인덱스를 직접 다시 그립니다(`tools/gfxpatch.py`). 팔레트는 바꾸지 않고, 원본에서 쓰인 색을 밝기순으로 골라 글자·안티에일리어싱에 씁니다.
